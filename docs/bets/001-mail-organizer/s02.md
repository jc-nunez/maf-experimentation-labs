# Slice 2: Mail assistant shell (harness agent, skills, MCP read-only, interactive)

## Demo
When done, I can run `mafx run mail/assistant` and, in one interactive session on my real outlook.com mailbox:
| I ask | I see |
|---|---|
| "what needs me this week?" | triage table (skill `triage`, tool `mail_digest`) |
| "who floods me?" | top senders, newsletters, unread piles (skill `sender-insights`) |
| "plan a cleanup" | proposed bulk actions with counts; nothing executed (skill `cleanup-planning`) |
| "suggest filing rules" | proposed folder/category rules; nothing created (skill `filing-rules`) |

## Design
```
 mafx run mail/assistant  (interactive; approvals relayed by mafx)
      │
 ┌────▼──────────── agents/assistant.py ────────────────────────────────────────┐
 │ create_harness_agent(                                                        │
 │   agent_instructions = chief of staff for mail; propose, never execute       │
 │   skills_paths       = projects/mail/skills/                                 │
 │   file_memory_store  = ~/.mafx/mail/memory/   (persistent, user home)        │
 │   todos + plan/execute modes: on · web search: off )                         │
 │ tools from project.yaml: mail-digest (own, slice 1) · outlook (MCP stdio)    │
 └────┬───────────────────────────────┬─────────────────────────────────────────┘
      │                               │
 skills/                         outlook  kind: mcp, transport: stdio
  triage/SKILL.md                  command: npx -y @softeria/ms-365-mcp-server@<pinned> --read-only --preset mail
  sender-insights/SKILL.md         env: MS365_MCP_CLIENT_ID: ${MAIL_OUTLOOK_CLIENT_ID}
  cleanup-planning/SKILL.md             MS365_MCP_TENANT_ID: consumers
  filing-rules/SKILL.md            (own sign-in cache, separate from mail_digest's MSAL cache)
```
- **Harness:** `create_harness_agent` supports `skills_paths` and `file_memory_store` natively (verified in agent_framework 1.21).
- **Skills:** each `SKILL.md` = when to use, steps, tools to call, output format (tables), rule "propose only". No scripts in this slice.
- **Platform change (host):** manifest `kind: mcp` gains `env` (with `${VAR}` expansion from the environment),
  `allowed_tools`, `approval_mode`; passed to `MCPStdioTool`. Update `docs/manifest.md`. Python host only (the .NET host
  does not load manifest tools; parity gap already tracked).
- **User home:** `MAFX_USER_HOME` (default `~/.mafx`). Move the slice 1 token cache there; accept the old path once
  and print a one-line migration note.
- **Decision (Jean, 2026-10-10):** use softeria `ms-365-mcp-server`, a community project (no official Microsoft MCP
  server exists for personal outlook.com). Mitigations: own app registration, pinned version, `--read-only`, local
  only, source review of the pinned release before first use.
- **Pin:** resolve the current `@softeria/ms-365-mcp-server` version, pin it in `project.yaml`; requires Node >= 20.

## Learned from the slice 1 demo (2026-10-11)
| Finding | Change in this slice |
|---|---|
| 7 days hit the 500-message cap (466 unread) | `mail_digest`: page through up to `max_messages=3000` by default; select minimal fields; report truncation explicitly |
| About 47% of the week is newsletters and promos (~85 senders), about 2% needs Jean | `cleanup-planning` leads with unsubscribe and archive-by-sender candidates, ranked by volume |
| Unsubscribe needs the `List-Unsubscribe` header | `mail_digest` selects `internetMessageHeaders` only when asked (`include_unsubscribe=true`); per-sender flag `can_unsubscribe` |
| Security alerts (new sign-in, new app) landed in Notifications | `triage` rule: account security alerts always go to Needs me |
| Output glitches: a table split by a blank line, a placeholder row | skill output rules: one contiguous table per bucket, no placeholder rows, empty bucket = one line "none" |
